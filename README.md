# 闪学it-51cto-老汤大数据课程之 Hadoop 3

获课：shanxueit.com/14375/51cto-老汤大数据课程之 Hadoop 3


大数据筑基必修课，老汤 Hadoop3 课程核心知识点梳理
学大数据绕不开 Hadoop，但很多人对它的认知停留在“听说过 HDFS 和 MapReduce”。真到上手才发现，Hadoop3 的知识点像一张网：存储、调度、计算、生态环环相扣，缺一块就串不起来。老汤这套 Hadoop3 课程定位“筑基”，不是堆 API 手册，而是把每个模块的设计动机、核心机制和适用边界讲透。梳理下来，几个板块最值得反复咀嚼。

第一块：HDFS——理解“分布式存储到底难在哪”。 课程没有一上来讲命令，而是先抛出问题：一台机器存不下怎么办？多台机器存了，怎么保证不丢、怎么保证读写快、怎么让上层无感知？沿着这条线，HDFS 的设计就顺理成章了。NameNode 管元数据、DataNode 存实际数据块，主从架构换来简单和高效，代价是 NameNode 成为单点。课程重点讲了副本机制、机架感知、读写流程和 SecondaryNameNode 的真实作用。尤其强调一个常见误区：SecondaryNameNode 不是热备，它只做检查点合并。Hadoop3 的纠删码和高可用方案也做了对比讲解，让人明白什么场景该用多副本、什么场景适合纠删码。存储层吃透了，后面很多问题都能溯源到这里。

第二块：YARN——资源调度的“分权艺术”。 很多人学 YARN 只记 ResourceManager 和 NodeManager 两个角色，课程却把“为什么要把资源管理和任务调度拆开”讲得很清楚。拆开之后，计算框架不再各自抢资源，集群利用率上来了，多租户也成为可能。核心知识点包括资源模型、调度器类型、容器生命周期和任务提交流程。课程特别对比了 FIFO、Capacity 和 Fair 三种调度器的适用场景，并指出生产环境里队列设计往往比选调度器更影响体验。YARN 这一块学扎实，后面理解 Spark on YARN、Flink on YARN 都会轻松很多，因为资源申请的底层逻辑是同一套。

第三块：MapReduce——计算模型的“分而治之”。 MapReduce 今天直接写的机会不多，但它的思想仍是分布式计算的底子。课程把重点放在 Shuffle 上，因为这是 MapReduce 最复杂也最容易被面试追问的部分。分区、排序、溢写、合并、拉取、归并，每一步为什么存在、什么情况会拖慢、哪些参数能调，都讲得比较细。课程还花时间讲了 Combiner 和 Partitioner 的使用边界，以及数据倾斜的典型表现和缓解思路。学完这一块，再看 Hive 的底层执行和 Spark 的宽窄依赖，会有“原来如此”的感觉。计算模型的理解比会写 WordCount 重要得多。

第四块：生态组件——知道每个工具“坐在哪把椅子上”。 课程没有把 Hadoop 讲成孤岛，而是把 Hive、HBase、Sqoop、Flume、Zookeeper 等组件的定位和协作关系串了一遍。Hive 把 SQL 翻译成计算任务，适合离线分析；HBase 补上随机读写能力，适合点查和实时场景；Sqoop 管关系型数据库进出，Flume 管日志采集，Zookeeper 做协调。每个组件不展开到源码级，但讲清楚“解决什么问题、和 HDFS/YARN 怎么配合、什么场景不该用”。筑基阶段最怕的就是工具学了一堆、不知道什么时候该掏哪个。这张生态地图，比单独精通某个组件更有长期价值。

第五块：集群运维与调优意识。 课程后半段涉及集群规划、配置文件组织、常见故障排查和基础调优。比如小文件为什么伤 NameNode、数据块大小怎么定、内存和 CPU 怎么分配给容器、日志去哪看。这些内容不炫技，但决定了一个人能不能把集群跑稳。老汤的讲法偏实战：先给现象，再带排查路径，最后落到配置和设计。筑基课的价值不在于覆盖所有参数，而在于建立“出问题知道往哪看”的直觉。

整体梳理下来，老汤 Hadoop3 课程的核心不是教多少命令，而是把分布式存储、资源调度、计算模型和生态协作这四根柱子立稳。Hadoop3 也许不是最新的技术，但它是理解大数据体系的最佳入口。筑基阶段把这张网织密，后面学 Spark、Flink、数据湖，才不是空中楼阁。
